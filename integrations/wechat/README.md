# 内置轻量微信网关

本项目直接嵌入 WeiLink 0.6.2（Python >= 3.10，零运行时依赖），复用其消息收发、上下文、限额与凭证持久化能力，不启动它自带的 Web 服务，不安装 OpenClaw、Node.js、浏览器或大模型。二维码展示使用 SDK 自带的本地 SVG 编码，不把登录二维码交给第三方图片服务。

调研时已存在 `epiral/weixin-bot` 和 `Oaklight/weilink` 等轻量项目，因此没有从零重写通信 SDK。选择 WeiLink 是因为它兼容项目现有 Python 3.10、无需异步运行时或额外 Web 框架。其管理登录接口尚未公开为稳定 SDK API，本项目在 `wechat_gateway.py` 中集中适配固定版本的会话保存与二维码接口；扫码 HTTP 流程参考腾讯官方插件 2.4.10，支持登录地域重定向，并限制服务地址在 HTTPS `weixin.qq.com` 域名下。后续升级 SDK 需验证适配层，不要直接放宽版本。

上游参考：

- WeiLink 源码：`https://github.com/Oaklight/weilink`
- WeiLink 发行包：`https://pypi.org/project/weilink/0.6.2/`
- 腾讯官方插件：`https://www.npmjs.com/package/@tencent-weixin/openclaw-weixin`

## 1. 在设置页登录

1. 安装更新后的 `requirements.txt`，或自行重新构建项目 Docker 镜像并重建容器。
2. 保留原来的 `./config:/app/config` 挂载，不要清空配置目录。
3. 登录本项目 Web 页面，打开 **系统设置 → 微信网关 → 获取登录二维码**。
4. 用本人微信扫码并确认。登录完成会自动启用网关，该微信可以执行共用网盘命令。
5. 在微信中向机器人发送“帮助”，建立回复上下文；再点击页面的“发送测试消息”。

不需要额外开端口、复制技能或配置模型。登录失败、二维码过期时页面会提示重新获取；若微信要求配对验证码，页面会显示输入框，填写手机微信显示的数字后提交。配对码只在内存中临时使用，不保存到配置或返回给浏览器。能否成功登录受微信账号资格、客户端版本及上游服务可用性影响。

微信账号凭证、上下文和去重状态位于 `config/wechat/`，使用现有 Docker 配置卷持久化；该目录已加入 Git 忽略，默认限制目录权限。应用令牌只存 SHA-256 摘要。备份目录时将其视为敏感凭证，勿公开或跨不信任用户共享。

“退出此账号”只取消该账号未完成登录并删除其本地微信凭证，其他账号和共用任务不受影响；不代表远程撤销微信端授权，可按微信客户端提供的入口管理授权。退出登录保留应用令牌，“移除”账号则同时撤销绑定该账号的应用令牌。不要让两个容器同时使用同一个微信登录目录。

### 多人共用

在 **微信网关 → 添加微信账号** 中输入名称（例如“家人 A”），选中该账号，再点击“获取登录二维码”，由该用户的微信扫码。依次为其他人添加账号即可，最多 10 个账号，每次只允许一个扫码流程；已有登录继续收发，不必退出。

所有已绑定微信都可搜索、追剧、查看任务、设置公共参数和执行清理，**共享本项目现有百度账号、目录、任务和参数，没有每人独立网盘或权限隔离**。仅添加可信家人，不要公开二维码。每个账号仅接收其扫码本人指令，不把首个来信用户提升为管理员；同一个微信不能重复添加。

回复使用发起指令的账号，登录凭证、上下文、限额、消息去重及过期状态按账号隔离。单个账号退出、会话失效或通知失败不会停用其他账号。账号列表可选中管理、设为默认或移除。旧单账号登录自动保留为“原微信账号”，无需重扫；旧应用令牌固定绑定该账号，之后切换默认账号不会改变令牌接收人。

开启“网关推送任务通知”后，任务通知会分别尝试发送给所有已登录账号；默认仍关闭，公众号推送仍可单独使用。默认账号仅用于未指定账号的管理操作和新建应用令牌，不影响微信指令的回复路由。

## 2. 保留微信公众号通知

两条通道独立，既有公众号代码与配置不被替换或清空：

| 通道 | 用途 | 设置入口 |
| --- | --- | --- |
| 轻量微信网关 / ClawBot | 收取命令、回复执行结果、供可信应用发送文本 | 系统设置 → 微信网关 |
| 微信公众号模板消息 | 原有任务汇总、定时通知 | 系统设置 → 通知设置 |

网关的 **“网关推送任务通知”默认关闭**。可以仅用它接收指令，把自动转存结果继续交给公众号。开启后会对各个已登录账号分别尝试网关推送，不会取代公众号；一个账号发送失败会继续尝试其他账号，也不会阻止之前的公众号发送流程。

公众号配置在 **通知设置 → 启用通知 → 快速添加常用字段 → 微信公众号配置** 中填写并保存：

- `WxAppID`
- `WxappSecret`
- `WxopenId`：支持多个接收人，用英文分号 `;` 分隔，例如 `openid1;openid2;openid3`。发送时自动过滤空项、去掉首尾空格并去重，依次发送；单个接收人失败不影响其他接收人。
- `Wxtemplate_id`

已有以上参数无需重填；保持原值和“启用通知”。公众号 OpenID 与 ClawBot 的本人标识不是同一概念，不能互换。公众号发送仍受它自己的账号权限、消息模板和微信规则约束，不保证任意场景都能送达。

多接收人填写示例（整个名单填入同一个 `WxopenId` 字段）：

```text
openid1;openid2;openid3
```

请使用英文分号 `;`，不是中文分号 `；` 或逗号。单个接收人直接填写原来的 OpenID 即可。所有 OpenID 均须对应已配置的同一个公众号，不需要为每位接收人重复添加 AppID、AppSecret 或模板字段。

保存后点击“测试通知”，会依次向名单中的接收人发送，请分别确认是否收到。重复 OpenID 只发送一次；某个接收人返回错误或请求抛出异常时，会记录该次失败并继续处理其他人。遇到 access token 过期时，当前接收人最多刷新重试一次，避免无限重试阻塞后续发送。

Docker 部署首次升级需重建镜像并用新镜像重建容器；仅重启旧容器无法加载新代码。升级后，在 Web 页面修改名单并保存即可，无需为每次名单调整重新构建。单个接收人配置和已有公众号参数无需迁移。

ClawBot 的上下文有时限和发送额度，不能视为无限制主动推送通道。用户需要先发消息，窗口或额度失效后需再次发消息刷新上下文；SDK 还会限制每个上下文的发送次数。接口成功只表示微信 API 接受，不等于手机已送达。本项目不绕过上游限制，不将发送失败伪装成成功，也不在发送超时后自动重试，以免重复通知。

当前固定版本 WeiLink 0.6.2 的 `CONTEXT_TOKEN_QUOTA` 为 **10 条/上下文令牌**，不是每次调用可额外发送十条；普通通知也消耗同一上下文额度，SDK 按 24 小时上下文有效期管理。用户再发消息、取得新令牌后才能重置额度。为保留最终总结，追剧每次最多检查 18 个入口，每两个链接的最终结果用换行合并发送，最后不足两个照常发送，最多 **9 条结果 + 1 条总结**。不再发送开场连接提示或单独的“正在创建”提示；单条文本仍受本网关 12000 UTF-8 字节限制。若上下文额度已被其他消息消耗，仍可能提前耗尽，微信公众号通知继续保留，不受该 ClawBot 额度影响。

## 3. 微信命令

搜索客户端统一采用 `test.py` 验证的 `curl_cffi` 请求方式：iPhone Safari 请求头、`impersonate='safari17_0'`，请求 `/s/关键词` 并自动跟随跳转。默认搜索源和配置模板均为 `https://www.seedhub.cc`；已有配置仍使用 `media.base_url` 的值，可改成已验证的 `https://sidhub.cc`。依赖已加入 `requirements.txt`，重建镜像后生效，无需浏览器，也无需设置 `request_mode`（旧值会被忽略）。搜索只返回多个匹配项目的标题、年份/类型、评分与 ID，不访问百度网盘，也不创建任务；选择 ID 后才逐个提取百度链接并检查，每个入口之间至少间隔 0.2 秒。网络错误、网页验证或 HTTP 403 / 429 仍会明确报错，不保证任何出口都可访问；403 不重试并记录 Cloudflare Ray ID，临时网络错误最多尝试三次。

仅执行固定网盘指令，不接受聊天指示去执行 Shell、安装软件或调用任意地址：

```text
帮助
搜索 三体
追剧 118943 每周六周日6-8点
任务
参数
设置 save_dir /追剧
追剧 118943 每天6-8点每30分钟
追剧 118943 cron 0 6-8 * * *
设置 max_results 5
设置 max_links 18
检查更新
```

可加 `网盘 ` 前缀，例如 `网盘 搜索 三体`。不支持任意自然语言推理。每个账号只接受登录时返回的本人微信标识所发的命令；多个绑定用户具有同样的共用任务管理能力。

先发送“搜索 影片名”，根据返回结果选择正确版本，再发送“追剧 数字ID [更新频率]”（例如 `追剧 118943 每周六周日6-8点`、`追剧 118943 每天6-8点每30分钟` 或 `追剧 118943 cron 0 6-8 * * *`）。未填写频率时，按最终选中资源的最新更新时间前后两小时，每天每 30 分钟检测。必须使用搜索结果中的 ID，不能再用影片名直接追剧。临时查询和读取分享失败最多重试 3 次；百度返回 `-7`（分享已删除或已取消）、`115`、`145` 等确定性错误不会重复重试。创建任务、微信回复和首次转存不自动重复，避免重复任务。每两个链接检查完成后合并回复最终结果，最后回复所选链接（含已知提取码）、更新频率、保存目录及检查统计，不再发送额外的连接或创建中提示。不会自动选择其他同名影片。“帮助”会直接返回文本，不再显示 JSON 的 `message` 包装。“检查更新”会扫描并清理明确失效或观察一周无更新的任务。回复失败不代表任务未执行，请先在 Web 或“任务”中确认，不要盲目重复创建。

搜索结果的每个匹配项目（标题、年份/类型、评分和 ID）使用一整行，项目之间换行。排查追剧失败时，可运行 `docker logs --since 10m -f baidu-autosave`，再发送一次指令。日志会依次记录 `追剧开始`、`SeedHub 响应`、`SeedHub 百度资源入口`、`百度分享检查通过`（或失败）、`追剧任务创建完成`、`启动首次转存线程`；用 `seedhub_id` 和 `task_uid` 对照定位。请求日志记录 HTTP 状态和最终域名；异常摘要记录异常类型、上游错误码及函数/行号，不输出原始异常中的凭证。新增日志不打印提取码、登录 token 或完整页面。任务已存在时会跳过首次转存，创建任务成功也不代表后台转存完成。

各账号使用独立后台收取线程，共用一个串行命令执行线程，耗时搜索不阻塞下一轮收取；单个账号网络错误会单独退避，不阻塞其他账号。共用命令队列最多 20 条，每个账号每分钟最多接纳 10 条；重复消息按账号和 ID（无 ID 时按内容摘要）去重，共持久化最近 2000 条。去重在执行前记录，服务中途退出可能使尚未完成的指令不再执行；这不是 exactly-once 队列，也不是持久化任务执行引擎。账号退出后，其尚未开始的排队命令会丢弃；已经开始的转存不因此撤回。

## 4. 其他 Docker / 应用共用

先选择接收账号，在 **微信网关 → 其他 Docker / 应用共用** 中创建应用，保存仅显示一次的令牌。每个应用一个令牌，固定绑定创建时选中的接收账号；不同接收人使用不同令牌。不要共用管理员 Web Cookie 或微信登录凭证。丢失令牌无法找回，应撤销后重新创建。

调用本项目已有 HTTP 端口：

```bash
export WECHAT_GATEWAY_TOKEN='在设置页面创建的应用令牌'
curl --fail-with-body \
  -X POST 'http://项目可达地址:5000/api/wechat/send' \
  -H "Authorization: Bearer $WECHAT_GATEWAY_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"text":"其他应用的任务已完成"}'
```

请求头与消息中不能携带微信登录 token。应用只能向绑定账号的扫码本人发送带 `[应用名称]` 前缀的文本，不能通过请求体改接收人、执行网盘指令或管理微信账号。每个应用每分钟最多 10 次发送尝试；文本和应用前缀合计最多 12000 个 UTF-8 字节。

同一个 Docker 自定义网络内可使用服务名；不同网络需按实际部署连接到同一个网络，或使用宿主机可达地址。容器内 `127.0.0.1` 不是宿主机。跨机器调用建议使用受控私网或 HTTPS，不要把该管理服务无保护地暴露到公网。

返回码：

- `200`：上游微信 API 接受，不保证手机送达。
- `400`：参数、限速、开关、登录或上下文条件不满足。
- `401`：应用令牌错误或已撤销。
- `403`：跨站请求被拒绝。
- `415`：未使用 JSON 请求。
- `502`：上游网络、会话额度或服务错误；发送结果可能不确定，不要盲目重试。
- `503`：网关未初始化。

Web 管理接口 `/api/wechat/status`、`settings`、`login`、`verify`、`logout`、`test`、`accounts` 和 `apps` 需要原有管理员登录。`login`、`logout`、`test`、创建应用令牌请求支持 `account_id`，省略时使用默认账号。`POST /api/wechat/accounts` 用 `{"name":"家人 A"}` 创建账号，`POST /api/wechat/accounts/<id>/default` 设置默认账号，`DELETE /api/wechat/accounts/<id>` 移除账号并撤销其应用令牌。它们不向前端返回登录 token 或上下文 token，响应禁止缓存。应用令牌仅适用于 `/api/wechat/send`。

## 5. 与旧 OpenClaw 集成的关系

上一轮未完成的 OpenClaw Compose、Dockerfile、初始化脚本与部署入口已撤回。既有 `integrations/openclaw/`、`clawbot.py` 和 `/api/clawbot/message` 作为可选兼容接口保留，不要求开启，也不影响新网关。若同时启用旧 OpenClaw 推送和新网关推送，可能收到重复通知，应只开启需要的渠道。

本方案没有增加独立公共网关容器；公共发送能力嵌入当前项目中，与当前服务同生命周期。它不是面向互不信任租户的隔离平台。
